# سند طراحی — سامانه جامع مدیریت انبار و کنترل پروژه سازمانی

## ۱) خلاصه و اهداف

سامانه‌ای کاملا **آفلاین** (بدون نیاز به اینترنت) و **چند کاربره** روی **شبکه محلی (LAN)** برای مدیریت:

- انبارداری کامل (کالا، رسید/حواله، موجودی لحظه‌ای، بارکد، چند انباره، هشدار کمبود)
- کنترل پروژه (پروژه‌ها، وظایف، پیشرفت، هزینه‌های اجرایی)
- مالی و خرید/فروش پایه (فاکتور خرید/فروش، تسویه، مشتریان/تامین‌کنندگان)
- مدیریت کاربران و دسترسی‌ها (نقش‌محور)

## ۲) معماری کلی

```
        ┌────────────────────────┐
        │   سیستم سرور (۱ عدد)    │
        │  Node.js + Express API  │
        │  دیتابیس SQLite (WAL)   │
        │   پورت ۴۵۰۰ روی LAN     │
        └───────────┬─────────────┘
                     │  HTTP/REST (شبکه محلی، بدون اینترنت)
       ┌─────────────┼─────────────┬─────────────┐
       │             │             │             │
 ┌─────▼─────┐ ┌─────▼─────┐ ┌─────▼─────┐ ┌─────▼─────┐
 │کلاینت PC 1│ │کلاینت PC 2│ │کلاینت PC 3│ │    ...    │
 │Electron+  │ │Electron+  │ │Electron+  │ │           │
 │  React    │ │  React    │ │  React    │ │           │
 └───────────┘ └───────────┘ └───────────┘ └───────────┘
```

**چرا این معماری؟**
یک سرور مرکزی سبک (Node.js + Express) روی یکی از سیستم‌های شبکه (یا یک مینی‌سرور/NUC اختصاصی) اجرا می‌شود و تنها مسئول اوست که با فایل دیتابیس کار کند؛ این کار مشکلات معمول SQLite در نوشتن هم‌زمان از چند پردازش را کاملا حذف می‌کند. اپ‌های دسکتاپ (Electron) روی هر سیستم کاربر نصب می‌شوند و صرفا از طریق HTTP با آی‌پی سرور در شبکه محلی صحبت می‌کنند — دقیقا مثل نرم‌افزارهای حسابداری رایج، اما بدون نیاز به اینترنت یا هیچ سرویس ابری.

- **بدون اینترنت:** تمام ارتباطات فقط در شبکه داخلی (LAN) رخ می‌دهد؛ فونت‌ها هم به‌صورت محلی در اپ باندل شده‌اند.
- **چند‌کاربره واقعی:** هر کاربر با نام کاربری/رمز عبور و نقش مشخص وارد می‌شود؛ عملیات هم‌زمان چند نفر (مثلا هم‌زمان ثبت رسید انبار و بستن وظیفه پروژه) به‌درستی مدیریت می‌شود.
- **قابل توسعه:** اگر در آینده نیاز به مقیاس بزرگ‌تر یا چند‌شعبه‌ای شد، فقط لایه دیتابیس (از SQLite به PostgreSQL) و بدون تغییر در API یا کلاینت‌ها ارتقا می‌یابد.

## ۳) مدل داده (ER خلاصه)

- **users → roles → permissions**: هر کاربر یک نقش دارد؛ هر نقش مجموعه‌ای از مجوزها (inventory.view/manage، project.view/manage، finance.view/manage، users.manage).
- **items → item_categories / units**: هر کالا به یک دسته و یک واحد اندازه‌گیری وصل است.
- **stock_documents → stock_document_items**: هر رسید/حواله یک سند با چند ردیف کالاست؛ نوع سند تعیین می‌کند که آیا موجودی افزایش یا کاهش پیدا کند (رسید خرید/مرجوعی/انتقال = افزایش، حواله فروش/مصرف پروژه/مرجوعی به تامین‌کننده/انتقال = کاهش، اصلاح = دستی).
- **stock_balances**: جدول موجودی فعلی هر کالا در هر انبار — با هر سند به‌صورت خودکار و در یک تراکنش اتمیک به‌روزرسانی می‌شود تا هرگز عدد ناسازگار نمایش داده نشود.
- **projects → project_tasks / project_costs**: هر پروژه چند وظیفه (با پیشرفت و وضعیت) و چند هزینه اجرایی (مصالح/نیرو/خدمات/سایر) دارد. حواله «مصرف در پروژه» می‌تواند مستقیما با هزینه پروژه لینک شود.
- **invoices → payments، suppliers، customers**: فاکتور خرید/فروش با وضعیت پرداخت‌نشده/جزئی/تسویه و تاریخچه پرداخت‌ها.
- **audit_log**: ثبت رویدادهای کلیدی برای پیگیری (در فاز بعد کامل می‌شود).

فایل کامل و قابل‌اجرای اسکیما: `server/src/schema.sql`

## ۴) دسترسی‌ها و نقش‌های پیش‌فرض

| نقش | دسترسی‌ها |
|---|---|
| مدیر سیستم | همه دسترسی‌ها |
| انباردار | مشاهده/مدیریت انبار، مشاهده پروژه |
| مدیر پروژه | مشاهده/مدیریت پروژه، مشاهده انبار و مالی |
| حسابدار | مشاهده/مدیریت مالی، مشاهده انبار |

نقش‌ها و مجوزها در دیتابیس قابل تعریف/تغییرند؛ رابط مدیریت کاربران (بخش «کاربران و دسترسی‌ها») برای افزودن کاربر و تغییر نقش او آماده است.

## ۵) طراحی رابط کاربری (UI/UX)

- زبان و جهت: کاملا فارسی و راست‌چین (RTL)، فونت وزیرمتن (باندل‌شده، بدون نیاز به اینترنت).
- چیدمان: نوار کناری تیره با گرادیان (ناوبری اصلی) + محتوای اصلی روشن با کارت‌های سایه‌دار و گوشه‌گرد.
- پالت رنگ: آبی/بنفش اصلی (#3B5BFD) + فیروزه‌ای تاکیدی (#12B3A8) + رنگ‌های وضعیت (سبز/زرد/قرمز) برای موجودی، وضعیت پروژه و فاکتور.
- کامپوننت‌های یکپارچه: کارت آمار (Stat Card)، جدول داده، پیل وضعیت رنگی، مودال فرم، نوار پیشرفت.

## ۶) ماژول‌های اضافه‌شده در نسخه دوم

علاوه بر هسته اولیه، موارد زیر نیز به‌طور کامل پیاده و تست شده‌اند:

1. **گزارش‌های پیشرفته + خروجی Excel/چاپ PDF**: کاردکس کالا (تاریخچه کامل ورود/خروج و موجودی لحظه‌ای)، سود و زیان پروژه (بودجه، تفکیک هزینه بر اساس نوع، حاشیه سود تخمینی)، خلاصه مالی/ترازنامه ساده (بر اساس مانده واقعی حساب‌های دفتر کل). خروجی اکسل با دکمه «دانلود اکسل» و خروجی PDF با دکمه «چاپ / PDF» (دیالوگ چاپ مرورگر/الکترون، انتخاب «ذخیره به‌صورت PDF» — کاملا آفلاین و بدون کتابخانه اضافه).
2. **نمودار گانت واقعی**: هر وظیفه می‌تواند به وظیفه دیگری «وابسته» باشد (پایان‌به‌شروع)؛ در تب «نمودار گانت» جزئیات پروژه، میله‌های زمانی بر اساس تاریخ شروع/سررسید و وابستگی‌ها نمایش داده می‌شود، همراه با خط «امروز».
3. **اسکن بارکد**: برای بارکدخوان‌های هندهلد (دستگاه‌هایی که مثل صفحه‌کلید عمل می‌کنند) یک فیلد «بارکد سریع» در فرم رسید/حواله وجود دارد که با اسکن+Enter، خودکار کالا را به سند اضافه می‌کند. برای اسکن با دوربین لپ‌تاپ/وبکم نیز دکمه «اسکن با دوربین» با کتابخانه ZXing (باندل‌شده، آفلاین) در فرم ثبت کالا و ثبت سند اضافه شده است.
4. **پشتیبان‌گیری خودکار**: هر شب ساعت ۲۳:۰۰ (قابل تغییر با `BACKUP_CRON` در `.env`) از دیتابیس نسخه پشتیبان گرفته می‌شود؛ آخرین ۲۰ نسخه نگه‌داری می‌شود. از صفحه «پشتیبان‌گیری» می‌توان پشتیبان دستی هم گرفت و فایل‌ها را دانلود کرد.
5. **اعلان‌های داخل‌برنامه‌ای**: زنگوله اعلان در بالای صفحه (هر ۳۰ ثانیه به‌روزرسانی می‌شود) هشدار کمبود موجودی و فاکتورهای نزدیک/گذشته از سررسید را نمایش می‌دهد.
6. **حسابداری دوطرفه**: دفتر حساب‌ها (Chart of Accounts) با کدینگ پیش‌فرض، ثبت خودکار سند حسابداری هنگام صدور فاکتور و دریافت/پرداخت وجه، امکان ثبت سند دستی (با اعتبارسنجی برابری بدهکار/بستانکار)، دفتر کل هر حساب، و مالیات بر ارزش افزوده روی فاکتورها (درصد قابل تنظیم).

## ۷) نقشه راه پیشنهادی برای فازهای بعدی

- گزارش سود و زیان کلی سازمان (نه فقط در سطح پروژه)
- اتصال فاکتور به سند انبار برای محاسبه خودکار بهای تمام‌شده کالای فروش‌رفته
- اعلان بر اساس ایمیل/پیامک (در کنار اعلان داخل‌برنامه‌ای فعلی)
- خروجی PDF اختصاصی (به‌جای چاپ مرورگر) برای فرم‌های رسمی مثل فاکتور رسمی
