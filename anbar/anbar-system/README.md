# سامانه جامع مدیریت انبار و کنترل پروژه سازمانی

سامانه‌ای آفلاین (بدون نیاز به اینترنت) و چند‌کاربره برای اجرا روی شبکه محلی (LAN)، شامل انبارداری کامل، کنترل پروژه، مالی/خرید و فروش پایه، و مدیریت کاربران و دسترسی‌ها.

سند کامل معماری و مدل داده: `docs/DESIGN.md`

---

## ساختار پروژه

```
anbar-system/
  server/     سرور مرکزی (Node.js + Express + SQLite) — روی یک سیستم در شبکه نصب می‌شود
  client/     اپ دسکتاپ کاربران (Electron + React) — روی هر سیستم کاربر نصب می‌شود
  docs/       سند طراحی و مدل داده
```

## پیش‌نیازها

- [Node.js نسخه ۲۲.۵ به بالا](https://nodejs.org) روی سیستمی که قرار است **سرور** را اجرا کند، و روی هر سیستمی که قرار است از سورس، اپ کلاینت را **بسازد** (build) یا در حالت توسعه اجرا کند. (نسخه ۲۲.۵ به بالا لازم است چون سرور از دیتابیس داخلی خودِ Node.js — یعنی `node:sqlite` — استفاده می‌کند؛ به همین دلیل هیچ کامپایلری مثل Visual Studio Build Tools لازم نیست و در شبکه‌هایی که دسترسی به GitHub کند/ناپایدار است هم `npm install` بدون مشکل کامل می‌شود.)
- تمام نصب‌ها فقط یک‌بار و از طریق اینترنت لازم است (برای دانلود بسته‌های npm از رجیستری npm)؛ پس از نصب، اجرای روزمره سامانه کاملا آفلاین است.

## مرحله ۱ — راه‌اندازی سرور (روی یک سیستم، مثلا کامپیوتر دفتر مدیریت)

```bash
cd server
npm install
copy .env.example .env      (در ویندوز)  یا  cp .env.example .env  (در لینوکس/مک)
npm run seed                 # ساخت دیتابیس اولیه + کاربر مدیر پیش‌فرض
npm start
```

پس از اجرا، پیام «سرور انبار روی پورت ۴۵۰۰ اجرا شد» نمایش داده می‌شود. کاربر مدیر پیش‌فرض:

- **نام کاربری:** `admin`
- **رمز عبور:** `admin123`

⚠️ حتما بلافاصله پس از اولین ورود، رمز عبور مدیر را از بخش «کاربران و دسترسی‌ها» تغییر دهید.

### آدرس IP سیستم سرور را پیدا کنید

- ویندوز: در Command Prompt دستور `ipconfig` را بزنید و مقدار «IPv4 Address» را یادداشت کنید (مثلا `192.168.1.10`).
- این آدرس همراه با پورت (`4500`) در کلاینت‌ها استفاده می‌شود.

### فایروال ویندوز

اگر کلاینت‌ها نتوانستند به سرور وصل شوند، باید پورت ۴۵۰۰ در فایروال ویندوز سیستم سرور برای شبکه محلی باز شود (Windows Defender Firewall → Advanced Settings → Inbound Rules → New Rule → Port → TCP 4500 → Allow).

**نکته درباره اجرای دائمی سرور:** برای این‌که سرور با روشن‌شدن ویندوز به‌صورت خودکار اجرا شود، می‌توانید از ابزار [pm2](https://pm2.keymetrics.io) یا Task Scheduler ویندوز استفاده کنید (`npm start` را به‌عنوان یک Startup Task تعریف کنید).

## مرحله ۲ — راه‌اندازی اپ کلاینت (روی هر سیستم کاربر)

### حالت توسعه (برای تست سریع)

```bash
cd client
npm install
npm run electron:dev
```

### ساخت نسخه نهایی قابل نصب (پیشنهادی برای استفاده واقعی)

```bash
cd client
npm install
npm install --save-dev electron-builder
npm run build
npx electron-builder --win portable
```

این دستور یک فایل اجرایی مستقل (`.exe`) در پوشه `client/release` می‌سازد که می‌توانید روی هر سیستم کاربر کپی و اجرا کنید (نیازی به نصب Node.js روی سیستم‌های کاربر نیست).

> برای سرعت دادن به فاز اول راه‌اندازی، همان حالت توسعه (`npm run electron:dev`) کاملا کاربردی و قابل‌استفاده است؛ ساخت فایل exe نهایی هر زمان که آماده توزیع گسترده‌تر بودید قابل انجام است.

### تنظیم آدرس سرور در کلاینت

هنگام اولین اجرا، در صفحه ورود روی «تنظیم آدرس سرور شبکه محلی» کلیک کنید و آدرس را به‌صورت زیر وارد کنید:

```
http://192.168.1.10:4500/api
```

(به‌جای `192.168.1.10` آی‌پی واقعی سیستم سرور را بگذارید). این تنظیم روی همان سیستم کلاینت ذخیره می‌شود و دفعات بعد لازم نیست دوباره وارد شود.

## نقش‌ها و کاربران

چهار نقش پیش‌فرض در سیستم تعریف شده: **مدیر سیستم، انباردار، مدیر پروژه، حسابدار**. از بخش «کاربران و دسترسی‌ها» (فقط برای مدیر سیستم قابل مشاهده است) می‌توانید کاربر جدید با نقش دلخواه اضافه کنید. جزئیات دسترسی هر نقش در `docs/DESIGN.md` آمده است.

## پشتیبان‌گیری از اطلاعات

تمام اطلاعات در یک فایل واحد ذخیره می‌شود: `server/data/anbar.db` (به‌همراه فایل‌های کمکی `anbar.db-wal` و `anbar.db-shm`). برای پشتیبان‌گیری، کافی است این پوشه را به‌طور دوره‌ای (مثلا هفتگی) در یک مکان امن کپی کنید — ترجیحا زمانی که سرور خاموش است یا با یک ابزار پشتیبان‌گیری که از snapshot سازگار با SQLite پشتیبانی می‌کند.

## ماژول‌های پیاده‌سازی‌شده در این نسخه

- ورود کاربران + نقش‌ها و دسترسی‌ها (JWT)
- انبارداری: کالا، دسته‌بندی، واحد، چند انبار، رسید/حواله با ۸ نوع سند، به‌روزرسانی خودکار موجودی، هشدار کمبود موجودی
- اسکن بارکد: ورودی سریع برای بارکدخوان هندهلد + اسکن با دوربین وبکم
- کنترل پروژه: تعریف پروژه، وظایف با پیشرفت/وضعیت/وابستگی، نمودار گانت واقعی، ثبت هزینه اجرایی
- مالی: مشتری/تامین‌کننده، فاکتور خرید/فروش با مالیات بر ارزش افزوده، ثبت پرداخت و پیگیری مانده
- حسابداری دوطرفه: دفتر حساب‌ها، ثبت خودکار سند از فاکتور/پرداخت، ثبت سند دستی، دفتر کل
- گزارش‌ها: کاردکس کالا، سود و زیان پروژه، خلاصه مالی — همه با خروجی Excel و چاپ/PDF
- پشتیبان‌گیری خودکار زمان‌بندی‌شده از دیتابیس + پشتیبان دستی
- اعلان‌های داخل‌برنامه‌ای برای کمبود موجودی و سررسید فاکتور
- مدیریت کاربران: افزودن کاربر، تغییر نقش، فعال/غیرفعال‌سازی
- داشبورد خلاصه وضعیت کلی سامانه

### تنظیمات اختیاری پشتیبان‌گیری (در فایل `.env` سرور)

```
BACKUP_CRON=0 23 * * *        # زمان‌بندی cron (پیش‌فرض: هر شب ساعت ۲۳)
BACKUP_RETENTION_COUNT=20     # تعداد نسخه‌های نگه‌داری‌شده
```

برای فازهای بعدی پیشنهادی به بخش «نقشه راه» در `docs/DESIGN.md` مراجعه کنید.
